# 在新窗口打开笔记（桌面端）

[English](2026-10-29-desktop-note-window.md)

## 问题与结果

实现 [Issue #67](https://github.com/tianma-if/edgeever/issues/67)。此前桌面端只能在主窗口中逐条编辑笔记。现在可以通过笔记的“更多”菜单，或“文件 → 在新窗口打开笔记”（`Cmd/Ctrl+Shift+O`）把笔记移到独立窗口，与主窗口并排或放到另一块屏幕上。

## 行为

| ID | 行为 | 验收 |
| --- | --- | --- |
| W01 | 一条笔记最多只在一个窗口中显示。移到新窗口前先保存主编辑器中的待保存修改；之后主窗口显示带“显示窗口”按钮的占位界面，而不是第二个编辑器。 | Electron 场景 A1：在主窗口输入的文字出现在新窗口中，主窗口不再有该笔记的编辑器。 |
| W02 | 通过菜单项、快捷键、笔记列表、快速切换、插件链接或占位界面再次打开同一笔记时，聚焦已有窗口，不会再创建一个。 | 单元测试“opens one window per note”；Electron 场景 A2。 |
| W03 | 关闭笔记窗口时先保存待保存修改，随后笔记以已保存内容重新在主窗口中打开。 | 单元测试“closing asks the renderer first”；Electron 场景 B1、B2。 |
| W04 | 移动前保存失败（例如本地存储 15 秒内无响应）时，笔记连同内容留在主窗口并给出提示。关闭窗口时保存失败，窗口保持打开并提示；再次关闭即关闭窗口，本地草稿会在主窗口中恢复。渲染进程无响应时，5 秒后的第二次关闭会直接关闭窗口。 | 失败保存与渲染进程卡死的单元测试；Electron 场景 D1（暂停存储）与 E1。 |
| W05 | 退出应用、切换账号或实例、清除会话或清除本地数据时，先请求每个笔记窗口保存，最多 5 秒后关闭。重启后不恢复笔记窗口。 | 单元测试“closeAll”；Electron 场景 F1（退出、重新启动、内容保留）。 |
| W06 | 笔记窗口只包含编辑器：指向其他笔记的链接在主窗口中打开，删除笔记会关闭其窗口，多条笔记可以各自拥有窗口。笔记窗口不能再打开窗口、切换账号、修改实例或启动插件。 | Electron 场景 A3、C1、C2、G1。 |
| W07 | 只有已存入存储的笔记可以移动；尚未创建完成的笔记显示“同步后在新窗口打开”。图表、表格、回收站和 Web 端不提供该操作。 | 手动检查菜单状态。 |

## 风险与回滚

本次改动仅涉及桌面端，没有数据、API 或迁移变化。原先只接受主窗口的主进程 IPC 中，会话令牌、图片上传、AI 直连请求和渲染错误上报现在也接受笔记窗口；账号、实例、数据重置和窗口命令仍只接受主窗口。同步 IPC 处理函数 `desktop:rich-text-heading-shortcut` 以前对其他窗口不返回值，会让窗口卡死；现在总会返回，且每个笔记窗口有独立的标题快捷键守卫。Electron 场景仅在 macOS 上对本地开发服务运行；Windows 与 Linux 由 CI 单元测试和构建覆盖，未做交互验证。回滚方式为 revert；没有持久化状态引用笔记窗口。
